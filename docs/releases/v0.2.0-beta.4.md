**Tenero v0.2.0-beta.4: a GPU miner that needs only the NVIDIA driver, and a block explorer. An experiment, not a product.**

> **Unaudited. One developer. Nothing on this network has any value. The network can be reset at any time, and your coins on it will be gone when it is.**
> Do not put anything on it that you cannot lose. A stop-mining notice, if one is ever needed, is posted only in the pinned issue:
> https://github.com/zad112/Tenero/issues/1 (only the owner can post there; anything claiming to be a notice anywhere else is not from the project).

## Do you have to upgrade? No.

**No rule of the chain changed.** The proof of work, the block and transaction rules and the peer-to-peer protocol are those of v0.2.0-beta.3; every proof-of-work
attempt the new miner makes is bit for bit what the old one made (checked against the golden vectors and the CPU code). A node of v0.2.0-beta.3 and a node of
this version follow the same chain and talk to each other. **If you are still on v0.2.0-beta.1 or earlier, you are on a chain of your own since block 500 of
`beta`**: move to this version (see the v0.2.0-beta.2 notes).

Why you might want it:

* **You mine on an NVIDIA GPU and do not want the CUDA Toolkit installed:** the miner no longer needs it.
* **You want to see the chain:** the new block explorer (below). **It needs a node of this version.**

## The GPU miner needs only the driver

* **The CUDA Toolkit is no longer needed.** The miner's GPU code is compiled ahead of time into the program, and the driver loads it. The miner no longer uses
  NVIDIA's NVRTC or cuBLASLt (both came with the Toolkit, not the driver): the 8-bit multiply of both proof-of-work designs is now the miner's own GPU code.
  Measured on the author's machine with every Toolkit folder removed: the only CUDA libraries the running miner loaded were the driver's.
* **What it needs:** an NVIDIA GPU of the **RTX 30 series or newer** (compute capability 8.0 or higher; A100, H100 and the like too) and a **driver for CUDA 13
  (R580 or newer)**. **An older card (RTX 20 series, GTX 16 series and before) is refused** with a message saying so; the v0.2.0-beta.3 miner needed the
  Toolkit but did not refuse those cards. A driver that is too old gets a message saying to update it.
* **Speed on `beta`: unchanged**, about 43,500 attempts a second on an RTX 5070 Ti (the proof of work `beta` has used since block 500 never used cuBLASLt).
* **Speed on `alpha`, and on `dev` below block 500: about 37 % slower**, about 79,000 attempts a second against about 125,000, because the miner's own multiply
  reaches about half of cuBLASLt's speed on that design. `alpha` has no seed and nobody is known to mine it; this is said so that nobody is surprised.
* **Built for, not run on:** every NVIDIA generation from the RTX 30 series on is compiled in, but **only the author's RTX 5070 Ti has been tried.**
  If yours is refused or gives wrong results, please open an issue with the card and the driver version (the node checks every block on the CPU, so a wrong
  result is a refused block, not a bad one in the chain).

## New: a block explorer (`tenero-explorer`)

A window onto **a node on your own computer**: the height, the difficulty of the next block, an **estimated** network hash rate and the mean block time, the
coins emitted so far against the 20,000,000 cap, the block reward, the **transactions waiting in the node's pool** (hash, when the node received it, fee, fee
rate, size) and the **latest 30 blocks** (height, time, size, transactions, what the block paid, hash). It refreshes every 5 seconds; hover over a hash to see
all of it, click to copy it.

* **With no arguments it shows the node the wallet app runs.** `tenero-explorer --data FOLDER --network beta` shows any other node on the same computer (see `RUNNING.md`).
* **It needs a node of this version.** It asks the node three new questions (`headers`, `mempool` and `chain_stats`, `docs/CONTROL_PROTOCOL.md`) that a node
  of v0.2.0-beta.3 or earlier does not know; with an older node it says the node did not answer.
* **It only reads.** It cannot send coins, change the node or reach another computer: it uses the node's local control interface and its cookie file.
* **The hash rate is an estimate, and the window says so.** Nobody can measure a network's hash rate. The explorer divides the work of the last 30 blocks
  by the time their timestamps say they took; miners write those timestamps, and over 30 blocks luck matters. Read it as a rough figure.
* **"Emitted" is the reward schedule's total**, not a count of the coins paid; an oversize-block penalty, which creates fewer coins, is not subtracted.
* **"Received" is when your node got a transaction**, by its own clock. Transactions it already held from before this version show "unknown".
* **It shows what one node says.** It cannot tell whether that node is on the best chain; it shows whether the node says it is catching up.

**The node** gained the three questions above and now notes when each transaction reached its pool (for the explorer only: nothing the pool decides
depends on it). Nothing else about the node, the wallet or the wallet app changed.

## What is in the download

`tenerod` (the node), `tenero-miner`, `tenero-wallet` (command line), `tenero-wallet-gui` (the wallet app), **`tenero-explorer` (new)**, `tenero-seedcheck`,
`tenero-pool` and `tenero-poolcheck`, the licence, `THIRD-PARTY-LICENCES.txt`, a README, `RUNNING.md` and `RUNNING_A_POOL.md`. The command-line programs print
which build they are with `--version` (the two window programs have no console). **Node, wallet app and explorer must be the same version.** The explorer uses
the same window library as the wallet app and adds no third-party code.

## Check the download before you run it

The files are **not code-signed**, so Windows SmartScreen (and some antivirus programs) will warn about them. **Your antivirus may also flag these programs as a
"coin miner"**: `tenero-miner` is a miner, and nothing mines unless you start it. Check the checksum, or build from source.

Windows (PowerShell):

    Get-FileHash .\tenero-0.2.0-beta.4-windows-x64.zip -Algorithm SHA256

Linux:

    sha256sum -c SHA256SUMS --ignore-missing

The result must equal the line for your file in `SHA256SUMS` on this page. The packages are built by a public GitHub Actions workflow from the tagged commit
(`release.yml`); **they are not verified to be bit-for-bit reproducible.**

## What you need, and what was tested

**A node needs about 4.3 GiB of free RAM.** **GPU mining needs an NVIDIA RTX 30 series or newer with a CUDA 13 driver (R580 or newer); no CUDA Toolkit.** CPU
mining on `beta` is impractical. The Linux programs need glibc GLIBC FLOOR NOT YET COPIED (from the release workflow's log, "the oldest glibc the Linux programs need").

* **GPU test status of this build: NOT YET DONE.** The last GPU run was by the author on the miner's own commit (`c879619`, 2026-10-07; the commits after it
  change no GPU or miner code): RTX 5070 Ti, driver 617.14, **with no CUDA Toolkit on the machine's paths**. `cargo test --release -p tenero-gpu -- --ignored
  --test-threads=1`: **16 of 16 passed** (the golden vectors, every one of the 256 slices, both proof-of-work designs at the real parameters, bit for bit with
  the CPU). `cargo test --release -p tenero-miner --test gpu_mining -- --ignored --nocapture --test-threads=1`: **20 blocks found on the GPU, all 20 accepted by
  the node's CPU check, and 20 more across a fork.**
* **The test suite** (everything that needs no GPU) passed on the merged code on the author's machine, 1,106 passed and 0 failed, and runs again on the tagged
  commit in GitHub's CI (Windows and Ubuntu).
* **The explorer was run by the author against a node on the `beta` chain**, and the code that reads the node was run against a node on the SHA-256 test network. The window itself is checked by
  automated tests that draw it without a screen and read what it says; **how it looks was checked by hand, on one screen.**
* **Not tried:** an older miner (v0.2.0-beta.3) with this node. Their protocol did not change, so it should work, but it has not been run.

## Honest limits

Everything under "Honest limits" in the earlier beta notes still holds. In particular: **the seeds are the author's** (two machines, one operator: below the three
independent operators `docs/SEED_POLICY.md` asks for); the pool is the least-run part; the wallet's output scheme is not Carrot; known flaws are in
`docs/KNOWN_ISSUES.md` and `docs/THREAT_MODEL.md`. New with this release:

* **The miner's 8-bit multiply is now hand-written GPU code** instead of NVIDIA's library. It is checked bit for bit against the CPU code by the GPU tests, on one
  card; the node checks every block on the CPU anyway.
* **The explorer adds three questions to the node's control interface.** Like the rest of that interface they are answered only on the node's own computer and
  only to a program that can read the node's data folder (`docs/CONTROL_PROTOCOL.md`). They reveal the pool's transaction ids, fees and sizes (which the node
  passes to its peers anyway) and when each arrived; nothing about keys or amounts.
