**Tenero v0.4.0-gamma.1: Dandelion++ and Tor, a 1% miner fee, AMD mining on Linux, and fixes. The same `gamma` chain. An experiment, not a product.**

> **Unaudited. One developer. Nothing on this network has any value. The network can be reset at any time, and your coins on it will be gone when it is.**
> Do not put anything on it that you cannot lose. A stop-mining notice, if one is ever needed, is posted only in the pinned issue:
> https://github.com/zad112/Tenero/issues/1 (only the owner can post there; anything claiming to be a notice anywhere else is not from the project).

> **This is a TEST release. "Released" here means "published for people to try": it does not mean finished, reviewed, audited or safe.**

## Everyone must upgrade: a new network protocol

**The chain does not change** (the same `gamma`, the same blocks, the same coins: your wallet and your node's data carry over as
they are). **The way nodes talk to each other does:** this release speaks **protocol version 3**, and **0.3.0-gamma.1 programs
(version 2) can no longer connect to it.** Both seeds and the pool switch to this release when it is published, so **a 0.3.0-gamma.1
node will find no peers** after that: its log shows failed connections, and its wallet sees no new blocks. Upgrade the node, the
miner and the wallet app together (download, close the old app, start the new one; nothing else to do).

* **Do not keep mining with 0.3.0-gamma.1 after the switch.** A miner alone on an old node mines a chain nobody else follows; its
  blocks are thrown away when the node is upgraded and joins the network again.
* **A wallet file saved by this release cannot be opened by 0.3.0-gamma.1** once it holds a payment or combine of more than 64 pieces
  (below). Keep your 24 words, as always.

## The miner now carries a fee: 1% of the mining time (`gpu` and `amd` on `gamma`)

**For one minute in every hundred**, a miner with the **`gpu`** (NVIDIA) or **`amd`** backend works for the author of that backend
instead of for you. The **`cpu`** and **`sha256`** backends have **no fee**, and neither do the `dev` and `test` networks.

| `gpu` (NVIDIA) | the project's author (zad112) | `TENgJhGzz31cRRVv9Xp5BEecw9Kxzf4qGiSCqYBH4JtFMfarVL2VvkbYFCPSGKfss7746sr65PuBqRoNWpShiR1yaNpE7jvrJTb` |
| `amd` | the AMD backend's author (qcvibes1) | `TENgJhA3h9GDHeXx3PVt7dT7Ef46C1rZ5VJWbohaourDDBNPGji6me2XgrmmXQ66vSgtnDGVkBpGyMR2sXdYcFaAedbkphU1sSL` |

* **How:** a time share. On your own node, the block template of a fee minute pays the fee's address; for a pool, the miner logs in
  with the fee's address for that minute. The first fee minute falls at a random point in the first 100 minutes. It is fair on
  average, not block by block.
* **It is shown, never hidden:** the miner's banner and log name the fee and who gets it, the screen says when a fee minute begins
  and ends, and a block found in one is shown as the fee's and not counted as yours. The wallet app shows it on the Mining tab and in
  Settings, and so does the node's own miner (`mine = gpu`).
* **It is fixed:** there is no setting to turn it off. The code is open (`crates/tenero-miner/src/fee.rs`, the addresses in
  `crates/tenero-app/src/mining_fee.rs`), and anyone may build a miner without it. Consensus is not touched: a fee block is an
  ordinary block. Details: `RUNNING.md`, "The mining fee".

## Network privacy: Dandelion++ and Tor

* **Dandelion++** (every node, nothing to set): a new transaction is first passed along a short random path of peers, one at a time,
  and only then announced to everyone, so the first announcement does not come from the node that made it (Monero's design and
  parameters; `docs/DANDELION_PLAN.md`). **Measured in a simulation** (12 nodes, a spy connected to every one, 24 transactions): the
  spy named the sending node for 23 of 24 without it, 6 of 24 with it. **Not measured on `gamma`.** With about ten nodes, mostly
  connected through the two seeds, the seeds' operator still learns a lot: it is not strong anonymity until there are many
  independent nodes. A node's own transaction is not in its own pool for a few seconds to a few minutes after you send it; the
  wallet shows it as sent all the same.
* **Tor** (optional; `docs/TOR_PLAN.md`, `RUNNING.md` "Tor"): with a Tor program running (the Tor Browser, port 9150, or the Tor
  Expert Bundle, port 9050), the node reaches `.onion` peers through Tor and sends **your own transactions through a Tor peer
  first**; with **"Every connection through Tor"** (`tor_only`), no peer learns your IP address (others then cannot connect to
  you). A node can have a `.onion` address of its own (`onion_listen`, `advertise_onion`); it never tells that address to a direct
  peer, or its IP to a Tor peer. The pool miner takes `--proxy` (and a pool may be `.onion`). The wallet app has both settings
  (Settings, Tor). **Tenero contains no Tor code and no new dependency**: Tor is the separate program you install. **Tested by the
  author with a real Tor program on the test network** (a node reachable only as a `.onion` service, another syncing from it with
  every connection through Tor); **not yet run on `gamma`**, and there is no `.onion` seed yet (one is planned for the author's
  server).
* Tor hides where you connect from, not what you pay (that is Carrot's and FCMP++'s business, unaudited), and it hides addresses,
  not timing.

## Mining on AMD (Linux): contributed, NOT tested by the project

A new package, **`tenero-0.4.0-gamma.1-linux-x64-amd`**, adds an AMD GPU backend (`amd`) for the **Radeon RX 7000 and RX 9000
series** (RDNA3 and RDNA4), on **Linux with ROCm 7** (built against ROCm 7.2.1; not the Radeon 780M/760M laptop chips). It was
written by an outside contributor, **qcvibes1**, who checked an earlier version bit for bit on their own RX 7000 card. **Nobody on
the project has an AMD card, and the version in this package has not been run by anyone**: CI only builds it. A wrong result
cannot get a bad block accepted (every node checks every block on the CPU), but it would waste your mining. If you can, **run its bit-for-bit
test first** (from the source code: the command is in `AMD_MINING.md`, in the package) and please report what happens. The ordinary Windows and Linux packages have no AMD
backend.

## Fixed

* **"Combine all" timed out and "Combine these" did nothing.** The wallet app made every proof (about a second a piece; a miner's
  thousand rewards are about 18 minutes of proofs) before showing anything, gave up waiting after two minutes, and let the next
  press queue behind the unfinished work. **Now** the summary (transactions, fee, and the estimated wait) comes first, at once; the
  proofs are made when you press Combine, **up to four transactions at once** (measured: 4 transactions of 10 pieces in 33.2 s on one
  thread, 8.8 s on four), with "transaction 3 of 11 made" shown while it works, and the buttons stay off until it is done.
* **After a big combine the wallet could not save** ("could not save the wallet file: the wallet file is damaged: count out of
  range"). A record of a sent transaction could name at most 64 pieces, and a combine spends about 95. Nothing was lost (the file on
  disk stayed as it was, and the transactions were valid), but nothing later reached the file. **Now** up to 4,096. A payment of more
  than 64 pieces had the same problem.
* **A block could lose most of its reward to the size penalty.** The node's block template filled a block to twice the penalty-free
  size whatever it cost: block 2,859 took 16 combine transactions and paid 3.4 TNR instead of about 21. **Now** the template goes
  past the penalty-free size only while each transaction's fee is more than the penalty it adds (Monero's rule); the rest wait for
  the next blocks. Not a consensus change.
* **Combining coins on a chain only a few blocks old panicked** (a tree of no layers). Found and fixed by an outside contributor,
  **gemsandgems** (PR #21). Thank you.
* The History tab's list and Settings scroll with the mouse wheel again.

## Check the download before you run it

The files are **not code-signed**, so Windows SmartScreen (and some antivirus programs) will warn about them. **Your antivirus may also
flag these programs as a "coin miner"**: `tenero-miner` is a miner, and nothing mines unless you start it. Check the checksum, or
build from source.

Windows (PowerShell):

    Get-FileHash .\tenero-0.4.0-gamma.1-windows-x64.zip -Algorithm SHA256

Linux:

    sha256sum -c SHA256SUMS --ignore-missing

The result must equal the line for your file in `SHA256SUMS` on this page. The packages are built by a public GitHub Actions workflow
from the tagged commit (`release.yml`); **they are not verified to be bit-for-bit reproducible.**

## What you need, and what was tested

**A node needs about 4.3 GiB of free RAM.** **NVIDIA GPU mining needs an RTX 30 series or newer with a CUDA 13 driver (R580 or newer).**
CPU mining on `gamma` is impractical. The Linux programs need glibc 2.34 or newer (the two window programs 2.35): Ubuntu 22.04 or newer.

* **GPU test status of this build:** NOT YET DONE (the author fills this in before publishing: the card, the driver, the date and the commit).
* **The test suite** (everything that needs no GPU) passed on the author's PC and in GitHub's CI (Windows and Ubuntu) on the merged
  code; the Python reference too.
* **Not run yet:** Dandelion++ and Tor on `gamma` (they start with this release), the AMD backend (above), the wallet app's Tor
  settings and the pool miner's `--proxy` with a real Tor program.

## Honest limits

* **The privacy code is not audited as used** (FCMP++ only partly, Carrot and the code around it not at all); the signatures and
  payment proofs are our own, reviewed by nobody. Unchanged from 0.3.0-gamma.1.
* **Dandelion++ and Tor are new and unreviewed**, and on a network this small they hide little from the seeds' operator.
* **The seeds and the pool are the author's** (two machines, one operator). Known flaws: `docs/KNOWN_ISSUES.md`, `docs/THREAT_MODEL.md`.
