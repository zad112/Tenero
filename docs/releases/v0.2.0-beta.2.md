**Tenero v0.2.0-beta.2: a hard fork of the `beta` network at height 500, and a miner about three times faster. An experiment, not a product.**

> **Unaudited. One developer. Nothing on this network has any value. The network can be reset at any time, and your coins on it will be gone when it is.**
> Do not put anything on it that you cannot lose. A stop-mining notice, if one is ever needed, is posted only in the pinned issue:
> https://github.com/zad112/Tenero/issues/1 (only the owner can post there; anything claiming to be a notice anywhere else is not from the project).

> **This is a TEST release. "Released" here means "published for people to try": it does not mean finished, reviewed, audited or safe.**

## UPGRADE BEFORE BLOCK 500 OF `beta`

**From height 500, `beta` blocks need a different proof of work. A node of v0.2.0-beta.1 or earlier refuses every `beta` block from height 500 on and stops at
height 499, on a chain of its own; a miner of v0.2.0-beta.1 or earlier makes blocks that this version refuses.** Your coins are not affected: blocks up to
499 are the same for both versions. **Upgrade the node, the wallet app and the miner together** (they are one download), before the chain reaches 500.
`tenerod status` prints the height. The `alpha` network does not change.

## The fork: the gathered proof of work (`docs/CONSENSUS.md` section 8.3)

* **What was wrong.** An attempt read one 16 MiB slice of the 4 GiB dataset, chosen by two cheap hashes of the nonce. A miner chooses its nonces, so it can try
  them 16 to a slice and read each slice once for all 16. The proof of work was then limited by how fast the card multiplies 8-bit numbers, not by its
  memory, which is exactly where data-centre GPUs and special chips lead most. **Worse, as a tester pointed out privately:** a
  miner could keep only the nonces that land on slice 0 and mine with that one 16 MiB slice, without the rest of the 4 GiB at all. **The author found this while making the miner faster** (the miner in this
  release does it for blocks below 500, so nobody is behind for those).
* **What changes.** From height 500 an attempt multiplies by 2,048 columns (8 KiB each) picked one by one from the whole dataset, so attempts share almost no
  reads and memory is the limit again. The dataset, the fold, the block id and the cheap check are unchanged. The rule is in `docs/CONSENSUS.md` 8.3, with
  golden vectors made by the Python reference (`tests/vectors/matmulhash_gather*.json`) that the Rust code reproduces bit for bit.
* **What this does not do.** No proof of work makes a data-centre GPU slower than a gaming card, and anyone can rent one; on a network this small, one
  rented card can out-mine everyone (`docs/THREAT_MODEL.md` E1, E12). The fork makes their lead smaller (an estimate from spec sheets, not a measurement:
  an H100's lead over an RTX 5070 Ti falls from about 5.7x to about 3.7x); it does not remove it.

## The miner

* **On `alpha`, and on `beta` and `dev` below height 500: about 120,000 to 125,000 attempts a second on an RTX 5070 Ti, against about 35,000 before.** Nonces
  are tried 16 to a slice, the keystream and fold kernels use memory better, and two batches are on the card at once. Measured by the author on one card
  (`docs/BENCHMARKS.md`).
* **From height 500: about 45,000 attempts a second on the same card** (measured with the benchmark, `gather_bench`; not yet over a long run on the
  network). The number is lower because the work is harder per attempt for everyone: what matters is your share of the network, not the number.
* The miner uses about 400 MiB more video memory than before.

## Check the download before you run it

The files are **not code-signed**, so Windows SmartScreen (and some antivirus programs) will warn about them. **Your antivirus may also flag these programs as a
"coin miner"**: `tenero-miner` is a miner, and nothing mines unless you start it. Check the checksum, or build from source.

Windows (PowerShell):

    Get-FileHash .\tenero-0.2.0-beta.2-windows-x64.zip -Algorithm SHA256

Linux:

    sha256sum -c SHA256SUMS --ignore-missing

The result must equal the line for your file in `SHA256SUMS` on this page. The packages are built by a public GitHub Actions workflow from the tagged commit
(`release.yml`); **they are not verified to be bit-for-bit reproducible.**

## What you need

As for v0.2.0-beta.1: **a node needs about 4.3 GiB of free RAM**; **GPU mining needs an NVIDIA GPU with a current driver and the CUDA Toolkit 13.x installed**;
CPU mining on `beta` is impractical.

* **GPU test status of this build: NOT YET DONE.**

## Honest limits

* **The fork height is fixed in the program, and there is no other activation mechanism.** If too few nodes upgrade in time, `beta` splits in two at block 500.
* **The new proof of work is the author's design and has had no outside review.** The claim that it is memory-bound was measured on one card (`docs/BENCHMARKS.md`);
  a chip with hundreds of MiB of on-chip memory could gain from it again (an estimate, `docs/THREAT_MODEL.md` E11).
* **The GPU kernel for the new proof of work is hand-written** (int8 tensor-core instructions); it is checked bit for bit against the CPU code by the GPU tests,
  and the node checks every block on the CPU anyway.
* Everything listed under "Honest limits" in the v0.2.0-beta.1 notes still holds: one seed per network, the author's; the pool is the least-run part; the wallet's
  output scheme is not Carrot; known flaws are in `docs/KNOWN_ISSUES.md` and `docs/THREAT_MODEL.md`.
