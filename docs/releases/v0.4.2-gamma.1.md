**Tenero v0.4.2-gamma.1: fixes for big payments and restarts seen on `gamma`, a list of your node's peers, the `.onion` seeds built in. The same `gamma` chain and the same protocol. An experiment, not a product.**

> **Unaudited. One developer. Nothing on this network has any value. The network can be reset at any time, and your coins on it will be gone when it is.**
> Do not put anything on it that you cannot lose. A stop-mining notice, if one is ever needed, is posted only in the pinned issue:
> https://github.com/zad112/Tenero/issues/1 (only the owner can post there; anything claiming to be a notice anywhere else is not from the project).

> **This is a TEST release. "Released" here means "published for people to try": it does not mean finished, reviewed, audited or safe.**

## Who should upgrade

* **Everyone who uses the wallet app to send payments, above all large ones (a "combine" of many coins): recommended.** In 0.4.1
  such payments could be lost or stay "pending" (below).
* **Nothing else changes:** the same chain, the same network protocol (3), so 0.4.0, 0.4.1 and 0.4.2 nodes talk to each other, and
  your wallet and your node's data carry over as they are. Download, close the old app, start the new one.

## Fixed: big payments and restarts (all seen on `gamma`, 2026-10-12 and 13)

1. **A big payment no longer stalls the node.** A transaction's proofs (FCMP++) were checked on the node's main loop, the one that
   also serves its peers and the wallet app: a combine of about 95 coins takes about 2 seconds a transaction, so the node stopped
   answering for tens of seconds. **Now** the proofs are checked first on the connection's own thread, and the loop finds the
   result already made (a failed result is remembered too, so a bad proof is not checked twice). *Not yet measured on `gamma`.*
2. **The wallet app no longer kills a busy node.** A node that had run for hours and did not answer for a moment was ended by the
   window as if it had never started, losing the payments it was still passing on, and stopping the miner. **Now** it is shown as
   "busy, not answering for now" and left alone; "Stop the node" still works.
3. **A node that stops cleanly sends its own waiting payments first.** Payments still on their Dandelion++ path are not saved, so a
   node stopped then lost them. **Now** it announces them to its peers before it closes (it gives them up to 3 seconds). **The
   price:** this node is then the first to announce those few payments, which says they came from it (the owner's decision).
4. **A restarted node gets the payments already waiting.** A node only heard of payments announced after it connected, so after a
   restart its miner mined empty blocks while others took the fees. **Now** each side of a new connection announces what is waiting
   in its pool, and a node that is syncing asks for what it heard of once it has caught up. No new message: 0.4.x nodes understand it.
5. **The wallet app no longer piles up memory while minimized.** Overnight that was about 20 GB, freed with a freeze when the window
   came back. Now only the latest picture is kept.
6. **The wallet app's height keeps moving** while a combine's proofs are being made (it stood still for minutes).

## New

* **`tenerod peers`** lists who your node is connected to: the address, in or out, through Tor or direct, how long, and the height
  each peer told of (`RUNNING.md`, "Who is it connected to"). A new control request (kind 22); nothing that existed changes.
* **The two `gamma` seeds' `.onion` addresses are built in**, used only when a Tor proxy is set (and alone with "Every connection
  through Tor", so the first connections never leave Tor). Without a proxy nothing changes. They are the same two machines and the
  same operator as the IP seeds.
* **"Let other nodes connect to me" and Windows Firewall:** Windows does not always ask to let the node through (not when the
  program already has a rule, even one for another port), and then nobody can reach you, with no warning. `TESTING.md`, "Letting
  others connect to you", now has the one-line rule to add yourself and how to test it from outside; the app's hint points there.
* **Pool and solo miner:** a block that came too late (another took the height) is counted as a lost race, not as "refused".

## Check the download before you run it

The files are **not code-signed**, so Windows SmartScreen (and some antivirus programs) will warn about them. **Your antivirus may also
flag these programs as a "coin miner"**: `tenero-miner` is a miner, and nothing mines unless you start it. Check the checksum, or
build from source.

Windows (PowerShell):

    Get-FileHash .\tenero-0.4.2-gamma.1-windows-x64.zip -Algorithm SHA256

Linux:

    sha256sum -c SHA256SUMS --ignore-missing

The result must equal the line for your file in `SHA256SUMS` on this page. The packages are built by a public GitHub Actions workflow
from the tagged commit (`release.yml`); **they are not verified to be bit-for-bit reproducible.**

## What you need, and what was tested

**A node needs about 4.3 GiB of free RAM.** **NVIDIA GPU mining needs an RTX 30 series or newer with a CUDA 13 driver (R580 or newer).**
CPU mining on `gamma` is impractical. The Linux programs need glibc 2.34 or newer (the two window programs 2.35): Ubuntu 22.04 or newer.

* **GPU:** **the GPU code is unchanged since 0.4.1-gamma.1**, whose GPU checks passed on the author's RTX 5070 Ti (16 of 16, mining
  end-to-end 2 of 2). **They were not run again on this build** (the author's GPU was mining). The GPU speed test now measures the
  attempt `gamma` really uses; it has not been run yet.
* **The test suite** (everything that needs no GPU) passed in GitHub's CI (Windows and Ubuntu) on the merged code, and the Python
  reference too.
* **Not measured yet:** how much fix 1 helps on `gamma` with a real big payment; fix 4 with real 0.4.1 peers (tested in the simulator).

## Honest limits

* **The privacy code is not audited as used** (FCMP++ only partly, Carrot and the code around it not at all); the signatures and
  payment proofs are our own, reviewed by nobody.
* **Dandelion++ and Tor are new and unreviewed.** Fix 3 above makes a node that stops name itself as the first to announce its own
  waiting payments.
* **The seeds and the pool are the author's** (two machines, one operator). Known flaws: `docs/KNOWN_ISSUES.md`, `docs/THREAT_MODEL.md`.
